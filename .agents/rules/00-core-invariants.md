# АВТОНОМНЫЙ ОПЕРАЦИОННЫЙ РЕГЛАМЕНТ

## 1. DEFINITION OF DONE (ОБЯЗАТЕЛЬНЫЙ АВТО-ЦИКЛ)
Если в рамках запроса менялся код, ЗАПРЕЩЕНО завершать ответ без проверок:
1. Запусти локальные тесты (npm test, pytest, go test). Если их нет на новый код — создай тесты (test-coverage-enforcer).
2. Проведи состязательный аудит diff (security-deep-audit) на BOLA/IDOR, инъекции и утечки.
3. При изменении эндпоинтов/сервисов проверь запуск на хосте (host-runtime-verify).
4. Circuit Breaker: при повторении ошибки 2 раза подряд — остановись и запроси решение у разработчика.

## 2. СКОРОСТЬ (VELOCITY)
1. Surgical Edits: меняй строго релевантный код. Не трогай соседние функции и форматирование.
2. YAGNI: никаких абстракций «на будущее».
3. Zero Fluff: отвечай сразу по делу (план -> diff -> отчет проверок).

## 3. БЕЗОПАСНОСТЬ
1. Zero Exposure: секреты только через переменные окружения.
2. Anti-Drift: параметризованные запросы в БД обязательны. Валидацию схем не отключать.
3. Строгая типизация: запрет на any в TS и нетипизированный код в Python.
4. Anti-Slopsquatting: проверка возраста библиотек (>60 дней в реестре).

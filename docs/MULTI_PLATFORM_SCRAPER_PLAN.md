## 2. РАЗГРАНИЧЕНИЕ ПРАВ И ТЕСТОВЫЙ РЕЖИМ (ADMIN VS TEST MODE)

Вся текущая бизнес-логика разделения доступа сохраняется на 100%:

### 2.1. Веб и Десктоп версии (`desktop.py` и Web Dashboard)
1. **Для тестовых и обычных пользователей (НЕ-админы):**
   * **Раздел «Биржи фриланса» полностью заблокирован:**
     В навигации висит иконка с замком `🔒`. При попытке перехода отображается экран:
     > **ДОСТУП ОГРАНИЧЕН**  
     > *Просмотр заказов биржи фриланса и управление аккаунтами доступны только администраторам системы.*
   * **API защита:**
     Эндпоинты `/api/fl/*` защищены `require_fl_access`. Любой запрос от пользователя с ролью, отличной от `admin` / `superuser` / `root` (и без валидного `X-Internal-Secret`), мгновенно отклоняется с кодом `HTTP 403 Forbidden`.
   * **Доступен ТОЛЬКО парсинг Яндекс.Карт:**
     При запуске сбора через `/api/search/start`:
     - Для тестов действует жесткий лимит: `effective_limit = min(req.limit, 10)` (в интерфейсе плашка: `РЕЖИМ ТЕСТА: ⚡ 10 компаний`).
     - Для пользователей с ролью `demo`: максимум 5 попыток с кулдауном 15 минут.
2. **Для Администраторов (`is_admin == True`):**
   * Полный доступ к разделу «Биржа фриланса»: все заказы со всех 9 подключенных бирж, фильтрация по платформам, статусам платности, добавление в избранное и скрытие.
   * Полный лимит Яндекс.Карт (слайдер до 100 компаний).

### 2.2. Telegram-уведомления (`dispatcher.py`)
* Уведомления о свежих заказах с ЛЮБОЙ биржи (FL.ru, Kwork, Upwork, Freelancer.com и др.) отправляются **СТРОГО И ИСКЛЮЧИТЕЛЬНО АДМИНИСТРАТОРАМ СТУДИИ**:
  ```python
  user_login = (getattr(user, "username", "") or "").lower().lstrip("@")
  is_admin_sub = (
      user_login in ("kupidon996", "ya_emildjan", "castleweb_admin", "admin")
      or (ADMIN_TELEGRAM_IDS and chat_id in ADMIN_TELEGRAM_IDS)
      or (str(chat_id) in ("1878543896", str(MANAGER_TELEGRAM_CHAT_ID)))
  )
  if not is_admin_sub:
      continue  # Тестовые и внешние пользователи НЕ получают коммерческие лиды!
  ```
* Обычные подписчики бота физически не могут получать пуши о заказах с бирж.

## 3. АНАЛИЗ РИСКОВ, «ДЫР» И ИХ УСТРАНЕНИЕ (Skill: `grill-idea`)

### Дыра №1. Коллизии идентификаторов заказов в БД
* **В чём риск:** На разных биржах ID могут совпасть (например, заказ `12345` на FL и `12345` на Kwork). При уникальном ключе только по ID один заказ затрёт другой.
* **Решение:** Вводим составной уникальный ключ `composite_id = f"{platform}_{external_id}"` (например, `kwork_3266573`, `fl_1658574`, `upwork_~0123abcd`).

### Дыра №2. Блокировки SQLite при параллельной записи (Database Locking)
* **В чём риск:** 9 сборщиков работают асинхронно. Одновременная запись в SQLite вызовет `sqlite3.OperationalError: database is locked`.
* **Решение:** Внедрение очереди `asyncio.Queue` и выделенного воркера записи в БД (`BatchDbWriter`), либо строгая блокировка через `asyncio.Lock` при коммитах транзакций.

### Дыра №3. Превышение лимитов Telegram Bot API (HTTP 429)
* **В чём риск:** При старте или залповом появлении заказов бот попытается отправить десятки сообщений одновременно и поймает бан от Telegram на 30–60 секунд.
* **Решение:**
  1. `TelegramRateLimiter`: отправка с паузой 1.2 секунды между сообщениями.
  2. Защита от спама при холодном старте: при первом запуске нового сборщика он сохраняет существующие проекты в БД, но в Telegram отправляет не более 3 самых свежих.

### Дыра №4. Падение одного сборщика вешает весь цикл
* **В чём риск:** Если Upwork не ответит из-за сбоя прокси, весь процесс опроса остальных бирж встанет.
* **Решение:** Независимые корутины для каждого источника через `asyncio.gather(*tasks, return_exceptions=True)`. Изоляция ошибок (Circuit Breaker): если биржа возвращает ошибку 3 раза подряд, интервал её опроса временно увеличивается до 5 минут с записью в лог.

### Дыра №5. Рассинхронизация папок `парсеп/parser` и `apps/parser`
* **В чём риск:** В проекте существуют две директории с кодом парсера. Изменение одной оставит вторую нерабочей.
* **Решение:** Модуль пишется в `apps/parser` и одновременно зеркалируется в `парсеп/parser` скриптом синхронизации, чтобы и Docker-версия, и Desktop-версия работали синхронно.

## 4. СТЕК ТЕХНОЛОГИЙ И STEALTH-ДВИЖОК ОБХОДА

### Проверка зависимостей (Safe Dependency Vetting)
* **Библиотека:** `curl-cffi` (версия 0.16.3).
* **Проверка:** 102 стабильных релиза, активная поддержка, используется для пробития Cloudflare и TLS-отпечатков без запуска тяжелого браузера.

### Архитектура маскировки:
1. **TLS Fingerprint:** Имитация `Chrome 124` (BoringSSL, GREASE-шифры, согласованный ALPN h2).
2. **HTTP Headers Pipeline:** Точный порядок заголовков Chrome (`:authority`, `:method`, `sec-ch-ua`, `sec-ch-ua-platform: "Windows"`, `User-Agent`, `accept`, `sec-fetch-dest`, etc.).
3. **Residential Proxy Gateway:** Для Upwork и Weblancer поддержка прокси в формате `http://user:pass@host:port` или `socks5://...`.
4. **Gaussian Jitter:** Случайное блуждание интервалов опроса (30с ± 7с) вместо фиксированного таймера.

## 5. КОНТРАКТЫ И МОДЕЛИ ДАННЫХ

### Модель нормализованного заказа (`NormalizedOrder`)
```python
@dataclass
class NormalizedOrder:
    composite_id: str         # f"{platform}:{external_id}"
    platform: str             # 'kwork', 'fl', 'upwork', 'freelancer', etc.
    external_id: str          # Исходный ID заказа
    title: str                # Заголовок проекта
    description: str          # Описание проекта
    url: str                  # Ссылка на заказ
    price_info: str           # "15 000 ₽", "$1,200", "Договорная"
    currency: str             # "RUB", "USD", "EUR", "UAH"
    is_free: bool             # True = бесплатный / базовый
    response_type_label: str  # "✨ Бесплатный отклик", "💼 Только PRO", etc.
    tags: list[str]           # Категории / навыки
    created_at: datetime      # Время обнаружения
    raw_payload: dict         # Исходный ответ площадки
```

### Абстрактный сборщик (`BaseFetcher`)
```python
class BaseFetcher(ABC):
    platform: str
    
    @abstractmethod
    async def fetch_orders(self) -> list[NormalizedOrder]:
        """Возвращает список свежих нормализованных заказов"""
        pass
```

### Сохранение обратной совместимости `FLOrder`:
В модель `FLOrder` добавляются поля:
* `platform: Mapped[str] = mapped_column(String(50), default="fl", index=True)`
* `response_type_label: Mapped[Optional[str]] = mapped_column(String(255), nullable=True)`
В методе `to_dict()` передаются все текущие поля (`id`, `title`, `price_raw`, `price_rub`, `is_free`, `url`, `is_favorite`, `is_hidden`), плюс `"platform"` и `"response_type_label"`. Текущий интерфейс Десктопа и Веб не ломается!

## 7. КРИТЕРИИ ПРИЁМКИ И ТЕСТИРОВАНИЕ

1. **Тест дедупликации:** Одинаковые заказы не записываются в БД повторно и не присылаются в Telegram дважды.
2. **Тест прав доступа:**
   - Не-админ в вебе/десктопе видит замок `🔒` и экран «ДОСТУП ОГРАНИЧЕН». В Яндекс.Картах получает максимум 10 лидов.
   - Не-админ в Telegram НЕ получает уведомлений о заказах с бирж.
   - Админ получает все заказы в реальном времени с правильными хэштегами и бейджами платности.
3. **Тест каждого сборщика:** Автономный скрипт подтверждает сбор живых данных с каждой площадки.
4. **Тест отказоустойчивости:** Падение/таймаут одной площадки не мешает работе остальных восьми.
